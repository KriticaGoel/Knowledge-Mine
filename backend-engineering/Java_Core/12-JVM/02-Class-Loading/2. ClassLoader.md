> A Class Loader is a JVM component responsible for locating, loading, 
> and making Java classes available to the JVM at runtime.

Class loader load the class Hello.class by searching the classpath and 
load the bytecode into memory using JVM and generate class Object.

Class object contain metadata of the class like class name(Hello), 
names of super class and its also include method name.

One class can create millions of objects, 
but its metadata is loaded only once by a Class Loader.

Suppose we have 10000 classes in our application. 
The JVM does NOT load all of them at startup.

The Class Loader **never creates objects.**

## Lazy Class Loading

Java uses Lazy Class Loading, which means classes are loaded only when they are first needed, not all at application startup.
```
Example
    import java.util.ArrayList;
    
    public class Test {
        public static void main(String[] args) {
            ArrayList<String> list = new ArrayList<>();
        }
    }
}
```
### What happens?
1. When you run java Test, the JVM first loads Test.class.
2. The main() method begins executing.
3. When the JVM reaches new ArrayList<>(), it realizes that ArrayList.class has not been loaded yet.
4. The JVM then loads ArrayList.class and continues execution.

### Key Point

Java does not load every class used by your application at startup. 
It loads classes on demand, when they are first referenced during execution. 
This approach is called Lazy Class Loading.

* Faster application startup.
* Lower memory usage.

## Why Does Java Have Multiple Class Loaders?

Handling **application classes** is very different from handling **JDK classes** and **platform classes**. To keep the JVM secure, optimized, and easy to maintain, Oracle designed a **Class Loader hierarchy** instead of using a single Class Loader.

Java provides three built-in Class Loaders:

### 1. Bootstrap ClassLoader

* Loads core Java classes from the JDK.
* Examples: `java.lang.String`, `java.lang.Object`, `java.util.ArrayList`.
* These are the fundamental classes required by every Java application.

### 2. Platform ClassLoader

* Loads Java platform modules and libraries that are not part of the core `java.base` module.
* Examples include classes from modules such as `java.sql`, `java.xml`, and other platform APIs.

### 3. Application ClassLoader

* Loads classes from the application's classpath.
* Examples: `Test.class`, `Student.class`, `Employee.class`, and other user-defined classes.

### Why three Class Loaders?

Using separate Class Loaders provides several advantages:

* **Security:** User applications cannot accidentally replace or override core JDK classes.
* **Modularity:** Each Class Loader has a well-defined responsibility.
* **Performance:** The JVM searches only the appropriate locations instead of searching everywhere.
* **Maintainability:** The JVM architecture remains clean, organized, and extensible.

**Note:** The Platform ClassLoader does **not** load native (C/C++) classes. Native libraries (`.dll`, `.so`, `.dylib`) are loaded through the **Java Native Interface (JNI)** using methods such as `System.loadLibrary()`.

## Parent Delegation Model

>Parent Delegation Model is a class loading mechanism in which a ClassLoader first delegates the class loading request to its parent. Only if the parent cannot load the class does the child attempt to load it.

In the parent delegation model, when a class loader is asked to load a class, 
it first delegates the request to its parent class loader. 
This process continues up the hierarchy until the bootstrap class loader is reached. 
If the bootstrap class loader cannot find the class, 
then the current class loader attempts to load it.

```
Application CL
      │
      │ "Can you load ArrayList?"
      ▼
Platform CL
      │
      │ "Can you load ArrayList?"
      ▼
Bootstrap CL
      │
      │ "I can load ArrayList!"
      ▼
```

Application ClassLoader doesn't load another copy.

It simply uses the class returned by Bootstrap.
```
Application CL
      │
      │ "Can you load Student class?"
      ▼
Platform CL
      │
      │ "Can you load Student class?"
      ▼
Bootstrap CL
      │
      │ "Not Found"
      ▼
Platform CL
      │
      │ "Not Found"
      ▼
Application CL
      │
      │ "I can load Student class!"
      ▼  
```

### Advantages
1. Security 

Core JDK classes cannot be replaced by application classes.

2. Avoids Duplicate Loading

Without delegation:

Bootstrap loads String

Application also loads another String

Now two versions exist.

❌ JVM chaos.

With delegation:

Only one copy is loaded.

3. Consistency

Every application uses the same core Java classes.

### Does the Application ClassLoader always load application classes?
"The Application ClassLoader receives the request first, but due to the Parent Delegation Model, it first delegates the request to the Platform and Bootstrap ClassLoaders. Only if neither parent can load the class does the Application ClassLoader load it."
