## Linking

Linking itself has three sub-steps.
```
Linking

Verification
↓

Preparation
↓

Resolution
```

### 2.1 Verification

The JVM verifies the bytecode is valid and safe.

This is one reason Java is considered secure.

Checks include:

* Is the bytecode valid?
* Has it been corrupted?
* Does it violate JVM rules?

If verification fails:
```
java.lang.VerifyError
```

### 2.2 Preparation

Now the JVM allocates memory for static variables and assigns them default values
```
Example:

class Student {

    static int count = 100;

}
```

During Preparation:

Memory is allocated for count.

But...

Its value is not 100 yet.

Instead:
```
count = 0
```
Why?

Because Preparation assigns default values.
```
Examples:

int → 0

boolean → false

double → 0.0

Object → null
```
### 2.3 Resolution

Now symbolic references become actual memory references.
```
Example:

Student s = new Student();
```
The JVM resolves references like:
```
java/lang/Object
```
into actual runtime references.
