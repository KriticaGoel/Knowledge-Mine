# 04_Heap

---

# 1. Definition

The **Heap** is the runtime memory area where the JVM stores:

- Objects
- Arrays
- Instance Variables

It is the **largest memory area** managed by the JVM and is shared among all threads.

---

# 2. Why Does JVM Need Heap?

Imagine storing every object inside the Stack.

```java
Person p = new Person();
```

If objects were stored in the Stack:

- They would disappear as soon as the method ends.
- Objects couldn't be shared between methods.
- Objects couldn't be shared between threads.

Instead, JVM stores objects in a separate memory area called the **Heap**.

---

# 3. Characteristics

✅ Shared by all threads

✅ Stores Objects

✅ Stores Arrays

✅ Stores Instance Variables

✅ Managed by Garbage Collector

✅ One Heap per JVM

# 5. Heap vs Stack

| Heap | Stack |
|------|-------|
| Shared | Per Thread |
| Stores Objects | Stores Method Frames |
| Managed by GC | Automatically Cleared |
| Larger | Smaller |
| Slower Access | Faster Access |

# 7. What Heap Does NOT Store

❌ Local Variables

❌ Method Parameters

❌ Methods

❌ Class Metadata

❌ Primitive Local Variables

```java

```

Output

```

```

Reason

Both references point to the same Heap object.

# 12. Reassigning Reference

```java
Person p1 = new Person();

Person p2 = new Person();

p1 = p2;
```

Before

```
Stack

p1 ---> Object1

p2 ---> Object2
```

After

```
Stack

p1 ---> Object2

p2 ---> Object2
```

Object1 becomes unreachable.

# 13. Garbage Collection Eligibility

An object becomes eligible for Garbage Collection when **no live reference points to it**.

Example

```java
Person p = new Person();

p = null;
```

```
Stack

p = null

------------------------

Heap

Person Object

(No references)
```

Object becomes eligible for GC.

---

# 14. Important Rule

Eligible for GC

≠

Immediately deleted

Garbage Collector decides when to remove it.

# 18. Why Heap Is Shared

Objects need to be accessible from:

- Multiple methods
- Multiple classes
- Multiple threads

Sharing Heap makes this possible.

---

# 19. Common Misconceptions

❌ Heap stores methods.

✔ Methods belong to Class Metadata.

---

❌ Heap stores local variables.

✔ Local variables live in Stack Frames.

---

❌ Objects disappear when method ends.

✔ Only unreachable objects become GC candidates.

---

❌ Every reference creates a new object.

✔ Multiple references can point to one object.

---

# Key Takeaways

- Heap stores all Java objects and arrays.
- Heap is shared by every thread.
- References live in the Stack, objects live in the Heap.
- Multiple references can point to the same object.
- An object is eligible for Garbage Collection only when no live reference points to it.
- Garbage Collection is automatic and controlled by the JVM.
