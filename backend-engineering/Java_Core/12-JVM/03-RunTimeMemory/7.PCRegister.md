# 03_PC_Register

# 1. Definition

The **Program Counter (PC) Register** is a small memory area inside the JVM.

Its job is to keep track of **which bytecode instruction the current thread will execute next**.

Think of it as a **bookmark** that tells the JVM:

> "Resume execution from this instruction."

---

# 2. Why JVM Needs PC Register

When a Java program executes:

- Methods are called
- Methods return
- Loops execute
- Recursion happens
- Threads switch

The JVM must always know **which instruction should execute next**.

Without the PC Register, the JVM would not know where to continue execution.

---

# 3. Responsibilities

The PC Register is responsible for:

- Tracking the next bytecode instruction
- Supporting method calls
- Supporting method returns
- Supporting loops
- Supporting recursion
- Supporting thread context switching

---

# 4. Characteristics

✅ One PC Register per Thread

✅ Thread Private

✅ Very Small Memory

✅ Stores Bytecode Instruction Address

✅ Automatically Updated by JVM

# 6. Thread-Private Memory

Each thread has its own PC Register.

```text
Thread-1

Stack

PC Register

-----------------------

Thread-2

Stack

PC Register

-----------------------

Thread-3

Stack

PC Register
```

This prevents threads from interfering with each other's execution.

---

# 7. What Does PC Register Store?

It stores the **address (or index)** of the next bytecode instruction.

Example bytecode:

```text
main()

0 : invoke greet()

1 : return
```

Initially

```
PC = 0
```

Meaning:

```
Execute instruction 0
```

---

# 8. Method Call Example

```java
public static void main(String[] args){

    greet();

}

static void greet(){

}
```

Simplified bytecode

```text
main()

0 : invoke greet()

1 : return

-----------------------

greet()

0 : return
```

Execution

```
PC = main(), Instruction 0

↓

Call greet()

↓

PC = greet(), Instruction 0

↓

Return

↓

PC = main(), Instruction 1

↓

Return
```


Notice:

The PC Register can move **forward** and **backward** because of jump instructions.

# 10. PC Register During Recursion

Example

```java
fun(3);
```

```java
void fun(int n){

    if(n==0)
        return;

    fun(n-1);

}
```

Deepest Stack

```text
Stack

fun(0)

fun(1)

fun(2)

fun(3)

main()
```

Important:

There is only **one copy of the bytecode**.

```text
Metaspace

fun()

0 : check

1 : recursive call

2 : return
```

Each recursive call creates a **new Stack Frame**, not a new copy of the method.

The PC Register always points to the instruction currently being executed.

---

# 11. PC Register During Method Return

Example

```text
main()

0 : greet()

1 : print()

2 : return

-------------------

greet()

0 : return
```

Execution

```
PC = main(), 0

↓

Call greet()

↓

PC = greet(), 0

↓

Return

↓

PC = main(), 1

↓

print()

↓

Return
```

The JVM resumes execution using the return information stored in the caller's stack frame.

---

# 12. Relation with Stack

The Stack stores:

- Method Frames
- Local Variables
- Parameters
- References
- Operand Stack
- Return Information

The PC Register stores:

- Next bytecode instruction

They work together.

---

# 13. Common Misconceptions

❌ PC Register stores Java code.

✔ It stores the address of the next bytecode instruction.

---

❌ PC Register stores objects.

✔ Objects are stored in the Heap.

---

❌ PC Register stores local variables.

✔ Local variables are stored in Stack Frames.

---

❌ All threads share one PC Register.

✔ Every thread has its own PC Register.

# Key Takeaways

- The PC Register keeps track of the next bytecode instruction to execute.
- Every thread has its own PC Register.
- It works closely with the Java Stack during method calls and returns.
- It supports loops, recursion, and thread context switching.
- It does not store objects, methods, or local variables.
