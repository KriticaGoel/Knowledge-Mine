# 05_Java_Stack

---

# 1. Definition

The **Java Stack** is a runtime memory area used by the JVM to execute methods.

Every thread has its **own Java Stack**.

Whenever a method is called, the JVM creates a **Stack Frame** and pushes it onto the Java Stack.

When the method finishes, the Stack Frame is removed automatically.

---

# 2. Why Does JVM Need Java Stack?

The JVM needs a place to store information required while a method is executing.

Example

```java
public static void main(String[] args) {

    int x = 10;

    greet();

}
```

During execution, JVM must remember

- Current method
- Local variables
- Method parameters
- Object references
- Return address

This information is stored in the Java Stack.

---

# 3. Characteristics

✅ One Stack per Thread

✅ Thread Private

✅ Stores Method Execution Information

✅ Automatically Managed by JVM

✅ Faster than Heap

# 5. One Stack Per Thread

Every thread owns its own Stack.

```text
Thread-1

Java Stack

-------------------------

Thread-2

Java Stack

-------------------------

Thread-3

Java Stack
```

One thread cannot access another thread's Stack.

---

# 6. What Does Java Stack Store?

The Stack stores **Stack Frames**.

Each Stack Frame contains

- Local Variables
- Method Parameters
- Object References
- Operand Stack
- Return Information

The Stack does **NOT** store objects.

Objects always live in the Heap.

---

# 7. Method Call Example

```java
public static void main(String[] args){

    greet();

}

static void greet(){

}
```

Execution

Step 1

```text

```

Step 2

```text
Stack

greet()

```

Step 3

```text
Stack

main()
```

The `greet()` frame is removed automatically.

# 8. Stack Frame

Every method call creates a Stack Frame.

```text
+----------------------------+

Stack Frame

-----------------------------

Local Variables

Method Parameters

Object References

Operand Stack

Return Information

+----------------------------+
```

Each Stack Frame belongs to exactly one method.

---

# 9. Local Variables

Example

```java
void test(){

    int x = 10;

    int y = 20;

}
```

Stack

```text
test()

x = 10

y = 20
```

Primitive local variables live inside the Stack Frame.

---

# 10. Object References

Example

```java
Person p = new Person();
```

```text
Stack

main()

p --------+

          |

          ▼

Heap

Person Object
```

The Stack stores only the **reference**.

The actual object is stored in the Heap.

---

# 11. Method Parameters

Example

```java
void greet(int age){

}
```

Stack

```text
greet()

age = 25
```

Method parameters are stored inside the Stack Frame.

---

# 12. Nested Method Calls

```java
main()

↓

A()

↓

B()
```

Stack

```text
TOP

B()

------------

A()

------------

main()
```

The most recently called method is always on top.

This is called **LIFO (Last In, First Out)**.

---

# 13. Method Return

When a method returns

```java
B();
```

Stack

Before

```text
B()

A()

main()
```

After

```text
A()

main()
```

The top Stack Frame is removed.

---

# 14. Recursion

Example

```java
fun(3);
```

```java
void fun(int n){

    if(n==0)
        return;

    fun(n-1);

}
```

Deepest Stack

```text
TOP

fun(0)

--------------

fun(1)

--------------

fun(2)

--------------

fun(3)

--------------

main()
```

Each recursive call creates a **new Stack Frame**.

The method bytecode is **not copied**.

Only Stack Frames are created.

---

# 15. Stack Overflow

Example

```java
void fun(){

    fun();

}
```

Every recursive call creates another Stack Frame.

Eventually

```
java.lang.StackOverflowError
```

occurs because Stack memory is exhausted.

---

# 16. Stack vs Heap

| Java Stack | Heap |
|------------|------|
| Per Thread | Shared |
| Stores Stack Frames | Stores Objects |
| Automatic cleanup | Garbage Collector |
| Faster | Larger |
| LIFO | No LIFO |

---

# 17. Why Stack Is Thread Private

Imagine two threads sharing one Stack.

Both threads could overwrite

- Local variables
- Method parameters
- Return information

This would corrupt execution.

Therefore each thread gets its own Stack.

---

# 18. Common Misconceptions

❌ Stack stores objects.

✔ Stack stores references.

---

❌ Objects disappear when method returns.

✔ Only references disappear.

Objects remain until unreachable.

---

❌ Stack is shared.

✔ Every thread has its own Stack.

---

❌ Every object has its own Stack.

✔ Threads own Stacks.

Objects live in Heap.

---

# 19. Important Rules

✅ One Stack per Thread

✅ One Stack Frame per Method Call

✅ Local Variables live in Stack

✅ References live in Stack

✅ Objects live in Heap

✅ Stack follows LIFO

# Key Takeaways

- Java Stack is used for method execution.
- Every thread has its own Java Stack.
- Every method call creates a new Stack Frame.
- Local variables, parameters, and references are stored in the Stack.
- Objects are never stored in the Stack.
- The Stack follows the LIFO principle.
- Stack Frames are automatically removed when methods return.
- Infinite recursion causes `StackOverflowError`.
