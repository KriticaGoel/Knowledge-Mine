>Stack follows LIFO — Last In, First Out.

## Why was Stack created?

Java's Stack was created to provide a LIFO data structure.

Its API gives you operations such as:
```
push()
pop()
peek()
empty()
search()
```
Example:
```
Stack<Integer> stack = new Stack<>();

stack.push(10);
stack.push(20);
stack.push(30);

System.out.println(stack.pop());  // 30
```

```
Stack
  ↓
extends Vector
```

## Internal Data Structure

Stack internally uses a Vector as its underlying data structure, which means it inherits all the properties and behaviors of a Vector, including synchronized methods and dynamic resizing.
```
Stack object
      |
      ↓
Vector state
      |
      ↓
Object[] backing array

┌────┬────┬────┬────┬────┐
│ 10 │ 20 │ 30 │    │    │
└────┴────┴────┴────┴────┘
              ↑
             top
```

## Time Complexity

| Operation  |     Complexity |
| ---------- | -------------: |
| `push()`   | O(1) amortized |
| `pop()`    |           O(1) |
| `peek()`   |           O(1) |
| `empty()`  |           O(1) |
| `search()` |           O(n) |

## Thread Safety

Stack inherits from Vector and its relevant operations are synchronized.

So:
```
Stack
↓
Vector
↓
synchronized legacy implementation
```
But here's the important modern Java point:

> Don't conclude that Stack is the best choice simply because it is synchronized.

It is a legacy design.

## Stack from Scratch

```
class MyStack<E> {

    private Object[] elements;
    private int top = -1;

    public MyStack(int capacity) {
        elements = new Object[capacity];
    }

    public void push(E value) {
        elements[++top] = value;
    }

    public E pop() {

        if (top == -1) {
            throw new RuntimeException("Stack is empty");
        }

        return (E) elements[top--];
    }

    public E peek() {

        if (top == -1) {
            throw new RuntimeException("Stack is empty");
        }

        return (E) elements[top];
    }
}
```
