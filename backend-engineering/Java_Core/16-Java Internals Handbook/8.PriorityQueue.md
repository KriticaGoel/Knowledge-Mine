## Part 2 — PriorityQueue

Normal Queue is FIFO, but PriorityQueue is not.
It orders elements based on their natural ordering or by a Comparator provided at queue construction time.

For Java's default PriorityQueue<Integer>, the smallest number has the highest priority.

```
LinkedList Queue:
insert: 30, 10, 20
poll:   30, 10, 20

PriorityQueue:
insert: 30, 10, 20
poll:   10, 20, 30
```

PriorityQueue internally NOT stores everything as a perfectly sorted list.

### why use heap?
Because we want:

* Insert → O(log n)
* Get highest priority → O(1)
* Remove highest priority → O(log n)

That's why PriorityQueue is useful.

### Internal Implementation of PriorityQueue

Java's PriorityQueue is implemented using an **array-backed binary heap**
>A binary heap logically, stored inside a backing array physically

Heap = logical data structure

Array = physical storage

```
             LOGICAL VIEW
             Binary Min-Heap

                  10
                /    \
              20      30
             /  \
           40    50
```

But Java does not create separate Node objects with left and right pointers.

Instead, it stores the heap in an array:

```
index:     0    1    2    3    4
          ┌───┬───┬───┬───┬───┐
array:    │10 │20 │30 │40 │50 │
          └───┴───┴───┴───┴───┘
```
The array represents this tree:
```
                    10  [0]
                   /        \
             20 [1]          30 [2]
             /    \
        40 [3]    50 [4]
```

Insert 5 . Min-Heap property is violated. So we need to heapify.
```
             5
           /   \
         20     10
        / \     /
      40  50   30
```

Array representation:
```
index:  0   1   2   3   4   5
        ┌───┬───┬───┬───┬───┬───┐
        │ 5 │20 │10 │40 │50 │30 │
        └───┴───┴───┴───┴───┴───┘
```


It uses a heap, specifically a min-heap by default. smallest element is at the top.

It guarantees that the head is the highest-priority element,
but iteration does not guarantee sorted order.


The rule is Parent ≤ children

```
5  <= 20 ✓
5  <= 10 ✓
20 <= 40 ✓
20 <= 50 ✓
10 <= 30 ✓
```

But there is no requirement that:
```
20 < 10 < 40 < 50 < 30
```
or that the entire array be sorted.

Only guarantee that the highest-priority element is at the head

### How does the array know the tree relationships?
For an element at index i:
```
Parent = (i - 1) / 2

Left child  = 2*i + 1
Right child = 2*i + 2
```
For example, index 1 contains 20:
```
Parent:
(1 - 1) / 2 = 0 → 10

Left:
2(1) + 1 = 3 → 40

Right:
2(1) + 2 = 4 → 50
```
No pointers are required.



### Why peek() is O(1)
The smallest element is always at the root:
```

          10  ← head
        /    \
      20      30
```

So Java can directly access it.
```
peek() → O(1)
```

### Why offer() is O(log n)
When we add a new element, it is added at the end of the heap (the next available position in the array).
Then, we perform a "heapify" operation to maintain the heap property.
This involves comparing the newly added element with its parent and
swapping them if necessary, which can take up to O(log n) time in the worst case.

Initially, the heap looks like this:
```
          10
        /    \
      20      30
     /  \
    40   50
```
Array representation:
```
index:    0   1   2   3   4
        ┌───┬───┬───┬───┬───┐
        │10 │20 │30 │40 │50 │
        └───┴───┴───┴───┴───┘
```
Step 1: Add 5 at the end of the array:
```
index:    0   1   2   3   4   5
        ┌───┬───┬───┬───┬───┬───┐
        │10 │20 │30 │40 │50 │ 5 │
        └───┴───┴───┴───┴───┴───┘
```
Heap representation:
```
          10
        /    \
      20      30
     /  \    /
    50   40  5
```

Step 2: Compare 5 with its parent (5-1)/2 = index 2 -> (30). Since 5 < 30, we swap them:
```
          10
        /    \
       20      5
     /  \    /
    50   40  30
```
Array representation:
```
index:    0   1   2   3   4   5
        ┌───┬───┬───┬───┬───┬───┐
        │10 │20 │ 5 │50 │40 │30 │
        └───┴───┴───┴───┴───┴───┘
```
This process is called heapify/sift up.

Step 3: Compare 5 with its new parent (2-1)/2 = index 0 -> (10). Since 5 < 10, we swap them:
```
          5
        /    \
       20      10
     /  \    /
    50   40  30
```

Array representation:
```
index:    0   1   2   3   4   5
        ┌───┬───┬───┬───┬───┬───┐
        │ 5 │20 │10 │50 │40 │30 │
        └───┴───┴───┴───┴───┴───┘
```

Now Parent<=child. this condition satisfied. Heapify is complete.

We do NOT sort the entire array.

We only move 5 upward until the heap property is restored

The height of a binary heap is:
```
O(log n)
```
Therefore insertion is O(log n).

### Why poll() is O(log n)

When we remove 10, we can't simply leave the root empty.

The heap has to rearrange itself to restore the heap property.

That takes up to the height of the tree:

```
O(log n)
```

Initially, the heap looks like this:
```
          5
        /    \
       20      10
     /  \    /
    50   40  30
```

Step 1: Remove the root (5) and replace it with the last element (30):
```
          30
        /    \
       20      10
     /  \    
    50   40  
```
Array representation:
```
index:    0   1   2   3   4
        ┌───┬───┬───┬───┬───┐
        │30 │20 │10 │50 │40 │
        └───┴───┴───┴───┴───┘
```

Step 2: Compare 30 with its children (20 and 10). The smallest child is 10.
Since 30 > 10, we swap them:
```
          10
        /    \
       20      30
     /  \    
    50   40  
```
Array representation:
```
index:    0   1   2   3   4
        ┌───┬───┬───┬───┬───┐
        │10 │20 │30 │50 │40 │
        └───┴───┴───┴───┴───┘
```

No check
```
10 <= 20 ✓
10 <= 30 ✓
20 <= 40 ✓
20 <= 50 ✓
```

Heap property restored.

This operation is called:

Sift Down / Bubble Down / Percolate Down

### Time Complexity Summary

| Operation        |   Complexity |
| ---------------- | -----------: |
| `peek()`         |     **O(1)** |
| `offer()`        | **O(log n)** |
| `poll()`         | **O(log n)** |
| `remove(Object)` |     **O(n)** |
| `contains()`     |     **O(n)** |
|remove() with no argument| **O(log n)**|

### Why is poll() O(log n) but remove(Object) O(n) in PriorityQueue?

`poll()` removes the root element, which is a simple operation in a heap.
`remove(Object)` has to find the element first (O(n)) and then remove it (O(log n)), making it O(n) overall.

poll() directly removes the root of the heap, so only heap reorganization is required, which takes O(log n).
remove(Object) must first search for the specified element
because a heap doesn't support efficient arbitrary-element lookup, making it O(n).


## PriorityQueue: Min-Heap vs Max-Heap

By default, java creates a min-heap, where the smallest element has the highest priority.

### What if we want the largest first?
We can create a max-heap by providing a custom Comparator to the PriorityQueue constructor.

```
PriorityQueue<Integer> pq =
        new PriorityQueue<>(Comparator.reverseOrder());
```

## Custom object with priority

```
class Employee {
    String name;
    int salary;
}
```

```
PriorityQueue<Employee> pq =
    new PriorityQueue<>(
        Comparator.comparingInt(e -> e.salary)
                  .reversed()
    );
```

## How does PriorityQueue grow its backing array when capacity is reached?
> PriorityQueue is backed by an array, but its size and capacity are different.

```
PriorityQueue<Integer> pq = new PriorityQueue<>(10);
```

initial capacity = 10

size =0

as data inserted, size increases.

When the number of elements exceeds the current capacity, the backing array needs to grow to accommodate more elements.



```
if (oldCapacity < 64)
    newCapacity = oldCapacity + (oldCapacity + 2);
else
    newCapacity = oldCapacity + (oldCapacity >> 1);
```


Notes:
1. PriorityQueue does not allow null elements. Because PriorityQueue needs to compare elements to maintain heap order, and null has no natural ordering.
2. PriorityQueue is not thread-safe. Use `PriorityBlockingQueue` for concurrent access.
3. PriorityQueue does not guarantee the order of elements with equal priority. If you need a stable priority queue, consider using a different data structure or implementing your own.
4. The internal array of a PriorityQueue may grow as elements are added. The default initial capacity is 11, and it grows dynamically as needed.
5. Duplicates allowed
